## 第一处阻塞及其放大过程

1. 第一包完整 messages 为 18,830 字符，宿主估算 6,616 token；provider 实报输入 6,028、输出 742。模型 `finish_reason=stop`，没有 timeout 或 length 截断。
2. 草稿形成三条观察：任务要求、读取答案模板的工具动作、官方反馈结果；它明确标注未看到 memo/API 查询/最终提交等正文。
3. 8 条引文中 4 条精确匹配，另 4 条评分引文失败。评分的 id 和 matched 值确实在已提供片段中；但反馈外层又把评分 JSON 序列化进 `reason` 字符串，原文含转义反斜杠，模型引用的是解码后的普通 JSON 形式。
4. 现行规则要求 quote 是原 fragment 的精确子串，因此拒绝符合冻结契约。这是表示层的复制失败，不能把这四个值称为编造；也不能由评分值真实推出业务归因正确。
5. 修复需要带上原消息、被拒草稿、诊断和修复限制，完整输入增到 24,228 字符，估算 **8,649 token > 单次 8,000 上限**。预检拒绝，第二次 SDK 调用没有发出。
6. 此时 Teacher 累计输入还剩 153,972、输出还剩 23,258；summary 累计输入还剩 25,972、输出还剩 3,258，另有 3 次调用额度。**不是累计预算耗尽。** 第一段失败后其余三段标为 `not_analyzed_after_stop`；没有先前有效摘要可复用，最终为 `trajectory_no_summary`。

原始错误、预检预算、草稿和用量保留在 [result.json](../../.trellis/tasks/archive/2026-09/09-19-post-rewrite-pilot/research/pilot/baseline/result.json)。[独立审查](../../.trellis/tasks/archive/2026-09/09-19-post-rewrite-pilot/research/independent-audit.md) 另外核实了真实 SDK 输入与 Teacher 输入相等、逐条引文对应关系、未发出的修复以及空候选/未发布状态。审查没有额外模型调用。

## 下一步修改建议与未测边界

建议先处理同一条因果链，另开版本验证，保留本次负结果：

1. **整理反馈的输入表示。** 将已解析的结构化反馈呈现为易读、可定位的证据块，并保留原始来源及确定的映射。避免要求模型从多层转义中复制引文。不能仅关闭引用校验，也不能静默把模型引文改成“通过”。
2. **为修复完整请求预留容量。** 初次 packet 装得下不等于修复装得下。包规划和预检要同时考虑提示词、schema、草稿、诊断及修复指令；明确保留修复余量或提高该阶段单次限额，并继续记账。仅增加全局调用次数解决不了本次问题。
3. **审视局部失败的停止范围。** 当前一次局部失败会使其他计划段停止。可在下一版本评估：局部引用/单请求容量失败时跳过该段并记录缺口，独立后续段在预算允许时继续；全局预算用尽必须停止。此项是待定修改，不是本轮已经实现或证明有效的行为。

这些修改之后仍需实际运行 extract → diagnose → propose → compare。当前只能确认局部整理的接口/容量阻塞，不能评价尚未产出的 Skill 是否具体、是否改善成绩。其他已知边界也继续保留：

- 4 个计划段仅投影 12/138 事件，第一包主要是任务、模板读取和评分；不能据此声称掌握了完整业务因果链。
- 该 Actor 未提供资源/实体依赖标记，本次计划没有 dependency support；官方反馈是评分组级结果，不能直接定位到某订单字段的失败原因。
- 本次 RunRecord 没有 reset-state/environment identity，comparability=false；没有实际对照，无法以本轮证据确认独立重复条件。后续效果实验要补足这类执行证据。
- 没有可控随机种子、没有重复测量、没有保留集运行，**学习收益、稳定性和泛化均未测得**。

本轮未改产品或补跑追求成功；保存 104 份可解析 JSON、6 对调用记录、冻结源码检查和独立审查。历史实验另见 [重写前诊断](gdpevo-context-pilot.md)，两者调用和样本不合并为一次效果实验。
