# 系统职责边界

这些边界来自用户已明确的项目方向，约束后续设计；它们不表示目标模块已经实现。

## 项目目的

从现成 Agent 的执行经历中形成可追溯的经验，维护可复用的程序性记忆，并用后续任务结果判断更新是否值得保留。不以复现某篇论文或发明新算法为前提。

## 三类文件不能混淆

| 文件 | 所有者及用途 |
| --- | --- |
| `.trellis/`、`.agents/skills/trellis-*`、平台 Trellis 文件 | 开发流程、规范、任务与上下文入口 |
| 根目录 `skills/memory-*/` | 当前产品提供给消费者的工作流指导 |
| 未来运行时经验、Skill 快照及验证记录 | 产品在明确的存储根下生成的学习资产；路径由实现协议确定 |

运行时学习器不能因生成 Skill 而改写 Trellis 规范、开发指令或消费者全局配置。新资产经过产品发布器交付；Trellis 只组织开发。

## 责任边界

- 原生 Agent 拥有模型推理、工具循环、working memory 和内部压缩；本项目不修改其权重或内部 Harness。
- Task/Environment 接入准备任务与环境；Agent 接入提供固定资产快照并采集可见事件；Feedback 接入拥有验收依据。三者不互相冒充。
- 经验提取器读证据、提出解释；Skill 修改器写候选；验证器运行检查；只有发布器切换 active version。
- 上下文提供器选择已发布且适用的内容；提供、读取、采用和有效是不同的证据层。
- Skill 缺失、未选中、内容错误、工具能力不足、环境问题和评测问题分别处理，允许不修改。
- 同一会话可以有多个目标和修订。反馈绑定它实际评价的要求及产物版本；暂停或取消不等于失败。
- 模型判断是代理反馈；不完整记录保留 unknown，不能通过摘要升级为事实。
- 一次执行锁定库版本。候选与已发布版本分开；涉及 Skill、引用和脚本的耦合修改一起验证、一起交付。
