# 经验学习系统架构设计

状态：设计草案，未实现。当前代码事实见 [当前架构](../../spec/backend/architecture-current.md)。本文件把已确定的职责边界与待测方法分开，不能据此声称已完成演化系统。

## 1. 核心模型

固定执行器配置，维护外部经验与程序性记忆。状态由经验池 M、库版本归档 V 和当前启用版本 a 构成；任务轮次 t、库版本 v、单个 Skill 修订号 r 分开记录。

首次生成是对空库提出 ADD；演化是对已有库提出 ADD/PATCH/RETIRE/NOOP。经验入池不等于发布，候选新版本不等于 active，保存历史版本不要求采用多分支搜索。

## 2. 数据流

```mermaid
flowchart TD
    T[Task / Environment Adapter] --> A[Agent Adapter]
    P[Context Provider] --> A
    S[(Published Skill Snapshot)] --> P
    A --> E[(Run / Event / Artifact Store)]
    E --> F[Feedback Provider]
    E --> X[Evidence Selector + Experience Extractor]
    F --> X
    X --> M[(Experience Pool)]
    M --> G[Skill Maintainer]
    S --> G
    G --> C[(Candidate Patch + Snapshot)]
    C --> V[Validation Runner]
    T --> V
    V --> R[Publisher]
    R --> S
    V --> H[(Rejected / Uncertain Evidence)]
```

开发 Trellis 不位于这条产品数据流中。用户任务结果可先交付；经验维护不要求阻塞每次会话。

## 3. 模块及写入权

| 模块 | 读取 | 写入 | 边界 |
| --- | --- | --- | --- |
| Task/Environment Adapter | 任务源、公开要求、环境配置 | 可重放初态或明确不可重放标记、目标修订 | 拥有任务/环境生命周期；不生成成功标签 |
| Agent Adapter | 公开任务、工作区、已固定资产快照、预算 | 可见事件、产物引用、客户端用量及采集缺失 | 不拥有真值，不修改原生 working memory |
| Run/Evidence Store | 实际采集字节与来源 | 只追加原始记录及派生索引版本 | 不把摘要当原始数据；不补造隐藏内容 |
| Feedback Provider | 对应要求、被测状态、检查定义 | 逐项结果、检查错误、来源与时间 | 对外部真值与模型 proxy 标明不同身份 |
| Experience Extractor | 按需证据、反馈、相关历史和反例 | 有边界的候选经验 | 解释属于假设，不直接修改 active 库 |
| Skill Maintainer | 经验池、当前库、允许编辑范围 | 结构化补丁、预期行为、验证计划 | 决定修改目标；允许 NOOP；不自批发布 |
| Validation Runner | 候选/基线快照、开发/回归任务、固定协议 | 成对结果、回归、失败及全部成本 | 调用同一 Agent/环境适配；不改评分标准迁就候选 |
| Publisher | 有效候选、验证记录、基础版本 | 不可变库快照及 active 指针 | 唯一发布写入者；检查基础版本，保留回退点 |
| Context Provider | 当前任务、适用且已发布的库 | 有预算的内容/引用及提供记录 | 本次实际读取/采用需另采证，不能由提供记录推定 |

逻辑模块可放在一个进程中，不要求拆成服务或每个模块单独使用一个 LLM。

## 4. 数据契约草案

这些是语义契约，不是现有 types.ts 或 schemas.ts 中已经实现的字段。

| 记录 | 最小语义字段 |
| --- | --- |
| GoalRevision | goal_id、revision、要求及来源事件、作用域、生效位置、替代关系、状态 |
| RunRecord | run_id、任务/要求版本、执行器/模型配置引用、初态引用、asset_snapshot_id、协议、预算、产物、结束状态 |
| Event | event_id、run_id、call/parent_id、类型、原文引用、相关目标、可取得的状态引用、complete/truncated/missing |
| Feedback | 检查 ID、criterion_ref、被测要求/状态、pass/fail/unknown、评价器状态、source、执行时间和到达时间、证据引用 |
| Experience | 条件、观察事实、候选指导、支持/反例引用、替代解释、缺失信息、适用范围及验证状态 |
| SkillRevision | 稳定 ID、修订号、触发范围、操作指导、引用/脚本资产及依赖 |
| LibrarySnapshot | snapshot_id、父版本、Skill 修订与资产清单、候选来源、验证记录、适用执行配置 |
| PatchProposal | proposal_id、base_snapshot、原子操作及目标、证据、预期行为变化、验证计划 |
| ValidationRecord | 协议/数据版本、任务和重复运行 ID、baseline/candidate、结果/异常/未知、逐项用量 |
| ReleaseRecord | 前后 active 指针、发布依据、操作者、时间、回退目标 |

一次会话不是一个 Run/Goal 的必然边界；一个目标的经历可跨不连续片段，事件也可关联多个目标。执行状态与检查结果分别表示。延迟结果不能默认属于反馈到达时的当前任务。

## 5. 经验提取与修改

1. 程序解析可见事件，建立工具/路径/测试/版本索引。
2. 建立用户要求及修订关系。Agent 自己的计划不能自动升级为用户要求。
3. 按反馈或已验收产物定位证据入口，补齐相关要求、修改、环境及恢复过程。
4. 按预算读取原文，输出事实、假设、缺失项与候选经验。
5. 检索同类经历及反例，对照已有 Skill 后决定 ADD/PATCH/RETIRE/NOOP。
6. 候选记录具体目标与基础修订；相关 Skill/脚本/引用作为一个包验证。

单次经历可支持窄范围候选；同题多次执行测波动；跨题经历测适用边界；旧/新版本对照测修改影响。具体采样策略是待实验选择，不能凭任意固定重复次数宣称规律成立。

PATCH 应受目标、允许字段/文件、基础版本及依赖约束。模型给出结构正确的操作不证明修改内容正确。第一版保留一个 active 版本，历史只用于审计、回退和离线比较。

## 6. 接入与反馈权限

Agent Adapter 只承诺它能观察到的消息、工具事件、产物和用量；无法提供的能力显式声明。原生 Skill、prompt 内容和工具入口是不同提供模式，实验中分别记录。

TaskSource 的公开输入与 evaluator 的私有验收材料分开。Solver 不应因统一 RunRecord 而取得原本不可见的答案；提炼器可见哪些反馈由评价协议规定。

benchmark 可给固定任务和 verifier；真实会话可给测试、review 和 proxy。两者共用维护核心，但不能把代理判断包装成基准真值。

接口可运行、资产可消费、跨 Agent 效果迁移是三个验收层次。第一版先一个执行器；第二个执行器分别验证接入和冻结经验迁移。

## 7. 验证、发布与回退

候选使用当前已允许的开发/回归材料验证，基线与候选保持任务、初态、执行配置、信息权限和预算可比。多次 reviewer 评分不是多次任务执行。

发布条件由预先固定的质量、回归、成本和证据门槛决定。门槛数值需先导数据支持，不在架构中写死猜测值。没有足够证据则保留候选或拒绝，active 不变。

Publisher 检查候选 base_snapshot 是否仍为预期基础。若其他候选已经发布，不把旧补丁直接覆盖到新库；重新基于新快照生成/验证，或保留为未采用分支。

库快照与依赖资产不可变；切换 active 指针是发布动作。正在执行的任务固定使用开跑时的快照，回退影响后续任务。多文件发布/并发语义尚未实现，须用故障与中断案例验证。

## 8. 评价与数据分离

- 在线协议：冻结维护策略；先记录任务 t 的成绩，才允许其反馈影响 t+1，不提前看未来答案。
- 冻结协议：冻结经验库，在未见任务上评价，测试时不更新。
- 开发集用于调策略；候选选择/回归集用于发布；最终报告集合不反向调同轮方案。
- 数据按任务/工作流/项目来源分组，不能把同题 retry 拆到不同集合。
- 记录全部分配槽位、异常、未知、救回、回归和全部费用；人工时间单列。
- 来源标注、目标/版本关联和证据支撑以真实会话审计；运行收益需可重放场景或后续任务实测。

SkillFlow 可验证跨任务维护机制，但固定目标和办公/数据任务不能证明动态会话或软件仓库维护已经解决。其逐任务 verifier 仍需核验。候选 benchmark 和边界见 [动态目标与评价协议](../../../docs/research/2026-09-17-agent-improvement/dynamic-goals-and-evaluation.md)。

## 9. 与现有代码的关系

保留 CLI-first 和 core 共享的入口习惯，先增量增加新协议，不把原 MemoryItem 强行解释成 RunRecord。旧 verified、confidence、retrieval_count 和 controller 分数不能迁移为新协议中的真值或收益。

当前存储可作原型基础，OpenViking 可作后续存储实现或比较对象；不将可替换存储后端变成首期必须重建的数据库。根目录产品 skills、Trellis 开发 skills、学习产物各有归属。

## 10. 决策与待证事项

已选：执行器外置；反馈单独适配；观测/假设/结果分开；局部候选；验证后发布；运行固定快照；真实使用与 benchmark 双入口。

待测：证据筛选优于普通检索的程度；单/多经历选择；归因模型；触发/检索方式；准入门槛；组合消融的收益；是否需要可执行 helper。

首期不承诺：自动理解所有会话、唯一因果归因、零回归、跨 Agent 无损迁移、无限上下文、已测性能提升。

## 11. 用户纠偏后的参考实现重点

2026-09-18：用户要求参考论文/源码推进完整实现，不以先导收益或项目必要性实验证明作为开工前提。以 [关键节点记录](requirements-ledger.md) 为当前需求解释。

- 经验选择：一例产生候选问题后检索相关经历和反例；支持同题多次执行，保存每次结果和来源。
- 归因：输出问题类型、事件/规则引用、替代解释及修改对象。缺少消费记录时不能确定地标为“未使用”。
- 更新目标：先查已有能力和触发范围；分别处理未提供、未选中、内容缺口、组合冲突、工具/环境/评价问题。
- Skill 关系：依赖、声明冲突、共同使用、测得影响是不同记录；局部对照须保留必要依赖。
- 版本选择：LibrarySelector 选择当前配置的 active 快照；SkillSelector 再选择该快照内适用于本任务的资产。候选最新不等于可执行版本。
- 运行检查：重复次数、预算和门槛是显式配置；记录全部结果，不用默认次数承诺统计稳定。
- 参考来源：SkillFlow 的接入与补丁、ReasoningBank 的经验提炼、Evo-Harness/SkillEvo 的整理与限定修订、SkillTriage 的证据归因、SkillSmith 的关联资产/版本检查、GEPA 的评价与反思材料分离。具体来源与迁移边界见关键节点文档。

这些是需要实现的机制。策略是否优于其他方案由后续评价回答，不能将其不确定性作为不推进参考实现的理由。
