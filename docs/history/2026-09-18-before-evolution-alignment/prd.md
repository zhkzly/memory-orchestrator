# Python 经验记忆系统参考实现

## 目标

本轮仅实现 Python 经验记忆核心：用户/项目记忆、已有经历的记录/提取/查找、Skill 更新/选择/验证/发布。由普通 Python 调用方提交轨迹与反馈。Codex/Claude、插件、MCP、专门 CLI 和运行器均不在本轮范围。

用户已授权按计划实现、独立审查并选择 Python 重写。旧 TS 产品在对应功能通过 Python 检查后移除；用户/项目记忆格式与数据保留。

## 要求

- 总纲 K01–K14/Q01–Q28 为范围依据，工作记忆归执行器。
- 用户/项目记忆只读提供，明确新增/纠正才写回；经验池和已发布 Skill 分开。
- 接收已有经历和有来源的反馈，不要求由本系统启动 Agent；未知与缺失不补造。
- 提炼/归因/提案有真实 schema、引用校验、补证/弃权/错误分支。
- 候选验证绑定完整快照；多次/多候选/批次用有限循环实现，单写者发布且可回退。
- 只围绕当前消费者实现函数/文件/任务池，不预建未来扩展框架。

## 验收

- [ ] Python 包可导入，公开核心 API 有直接调用样例。
- [ ] 临时真实文件/进程测试覆盖 checklist.md，独立 reviewer 复核数据流与偏离。
- [ ] scripted 模型与明确评测回调可走完整闭环，清楚标为测试证据。
- [ ] 环境允许时做有预算的真实 SDK 结构化调用检查，不启动 native Agent；失败与限制如实记录。
- [ ] 使用/评测入口和阶段状态有文档，旧 TS 按对应消费路径移除，用户数据保留。

## 边界

不提交/推送，不自动安装到消费者全局配置，不运行完整昂贵 benchmark，不声称未测收益。模型采用用户指定 gpt-5.6-terra 和环境凭据，不泄露密钥。
