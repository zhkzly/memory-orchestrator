# Python 记忆核心：当前实现边界

本轮只交付可导入的 Python 包和直接调用样例。没有 CLI、MCP、插件、Agent runner、Codex/Claude 接入。用户已确认该范围并要求继续完成。旧 TS 文件保持原样，不作为本轮接口约束；用户数据不删除。

## 三段交付

1. 用户/项目事实的明确保存与纠正、按范围召回；已有经历记录、已知 context 身份回传、延迟反馈追加。
2. 有界证据整理、经验提取/检索、归因、Skill 候选及依赖/冲突处理。
3. 调用方提供 evaluator，比较确切旧/新快照；通过既定规则才发布，可回退；完整记录失败和成本。

## 实际代码职责

- common.py/contracts 数据：少量共享 JSON/hash/error/schema 工具，不复制完整研究文档到运行时。
- store.py：本地记录、事实读写、经验检索、项目隔离、快照/候选/发布。
- learning.py：有界证据、OpenAI SDK、提取/归因/提案；只处理调用方提交材料。
- evaluation.py：调用普通 evaluator(snapshot, case)，记录结果并形成绑定版本的评价。
- engine.py：供调用方使用的直接方法，将上述流程组合起来。
- tests/ 和 examples/：真实本地文件及 scripted 模型/评价器的行为检查；不冒充 Agent 效果。

关系评分、多候选和批次仅在本轮流程有消费者处实现，使用普通函数与循环。无采集守护进程、模型自主调度器、策略 DSL、通用后端注册器。

## 数据责任

项目 scope 是宿主元数据，不能由模型扩大。缺反馈、缺 source snapshot、缺消费记录均可合法记录为未知；不创建假的运行组或上下文。可回传 recall 的 context_id，并通过 add_feedback 关联原经历和被测状态。

用户事实的明确纠正不经过 Skill 效果门。模型不能调用用户事实写入。经验可检索；候选 Skill 不进入默认执行指导。

候选评价由调用方负责实际任务与标准；核心只保证版本/案例/评价器身份绑定、全结果统计和发布条件，不宣称获得了操作系统隔离或自动独立真值。局部修复不强制证明迁移题严格提升；迁移范围另按所测证据报告。

## 开发与审查

明确分配文件 ownership；新文件先验收 RED，再实现 GREEN，再官方 mutation 检查。独立 review 同时检查逻辑与无当前用途的抽象。公共函数形状由 interfaces.md 维护，调整先由 main 统一，不并行造同义字段。
