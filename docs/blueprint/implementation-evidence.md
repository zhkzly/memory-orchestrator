## v1.8.1：区分模型语义与框架输入职责

[真实试跑](../experiments/gdpevo-post-rewrite-pilot.md)定位到反馈嵌套JSON引用失败和修复输入8649>8000的阻塞。本次没有把摘要、经验、原因假设、Skill必要性或提案改成业务硬编码：这些仍由LLM产生；引用、预算、受限修改和准入继续由框架执行。

- Feedback.reason原字符串使用独立来源与UTF-8坐标，旧完整Feedback引用保持。模型必须选对已提供的引用，宿主不自动补转义或把改写当原文。
- full/reason是同一反馈的两个视图，共享一份选材正文额度。首次实现曾重复常驻两份长正文，导致原42k磁盘测试丢orders返回；按同源共享规则修复后，原业务断言和原预算全部保留并通过。旧全文仍可补读，额外引用元数据照常计费。
- 仅校准参考summary单次输入为12k，原累计32000输入/4000输出、4次调用以及全局预算保持。真实拒绝稿的确定性重放在新提示词下估算6818/8851输入token；12k允许有限修复，8k仍在第二次dispatch前拒绝。这些是宿主估算和脚本响应，不是新实盘用量。

最终全部Python验收 **391项通过（85.055秒）**，包含原GDPevo适配检查。新增反馈视图/共享额度21项和修复容量4项均通过；官方evidence故障注入21项全部检出，另有两次修改前许可，run预算前/后两次许可。完整记录与独立审查保留于本轮Trellis任务。生成总纲与包单独同步检查，未用单元测试推导真实学习收益。

职责详见 [当前架构](../../.trellis/spec/backend/architecture-current.md)。当前代码链已接通；模型是否产生有用候选、候选是否通过比较以及是否发布，仍按每次实际运行结果分别报告。

## v1.8.0：统一轨迹学习入口

已将N06输入链重写为：按信息类型/目标/调用组构造计划 → 足够短的处理后视图直接提取，或按阶段预算局部整理 → 精确短引文与派生旁注 → 原有经验、诊断、Skill修改与验证。没有保留旧全局抽样后的可选包装路径；独立原文包工具仍供目标关联等消费者使用。

- 用户控制前缀、关键动作/参数、错误/验证结果、可见分析和普通工具正文分层；先按段重要性选择，再保持段内源顺序。重复普通结果可以折叠，来源/目标冲突不被抹平。
- 局部模型的叙述不是原文。宿主验证其精确短引文、计算UTF-8范围，保留匹配的行动/返回上下文；后续仅引用真实提供片段，目录和摘要ID不算已读原文。
- 有界依赖回找已接入实际学习输入，整轮共享新增邻居额度并保留原scope/版本；开关回归确证写入者能到达局部整理和上层提取，不以独立API存在代替消费。
- 完整模型请求、重试及补读均受全局/阶段计量限制；预算预留与provider报告分开。局部失败保留已完成记录、费用和未处理段状态，项目报告展示计划/分析/部分覆盖。

完整回归 **366项通过，84.252秒**。按用户随后提高参考上限的要求更新配置后，相关预算、实际输入和probe检查 **42项通过，2.012秒**。收尾官方故障变体 **66项全部检出并精确恢复**（evidence 18+8、model 18、学习/报告/参考配置18、demo 4）；结构检查另覆盖37个文档负例与6个生成视图检查。

本轮使用真实136事件fixture及明确标注的边界变体、注入的计数器和脚本Teacher，**没有真实模型调用或新的benchmark分数**。默认token计数为估算，预算限定于单个model实例；初始preview不预留后续份额，过紧配置仍可在部分整理后正常弃权。元数据绑定校验有额外扫描开销，选择事件上限不等于总I/O上限。原始失败、独立审查与最终日志见[本轮验收档案](../../.trellis/tasks/archive/2026-09/09-19-role-aware-trace-learning/research/verification.md)。

## 证据边界

- CSV处理、脚本、对照、持久化、恢复和版本切换实际在本机执行；构造教师的决策用于确定性检查，不是测量模型的学习能力。
- 目标关联、语义去重和归因仍是模型判断。协议校验能拒绝假引用/越界/缺证，不能证明自然语言解释为真；准确率需要另设独立标注。
- `measured_effect` 是固定案例与背景下的条件增量，适用范围/版本会参与实际选择。它不证明所有任务上的普遍因果。
- 真实benchmark、未见任务收益和扣除全部维护费用后的净收益未测。缺少价格、缺返回或未终结周期保持unknown。
- 默认Python资产执行器提供进程级限制，不提供OS沙箱；要求的隔离能力不可用就留下unknown。
- 浏览器URL策略仍限制视觉检查；HTML只做源数据、脚本语法与生成一致性检查，不绕过该限制。
