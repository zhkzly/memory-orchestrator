# 明确 LLM 与框架边界并修复局部证据学习阻塞

## Goal

基于真实失败区分语义推理与确定性框架职责，修复反馈证据表示和修复请求容量；保持归因、Skill 生成、评价与发布语义不变，完成有界真实回归。

## Requirements

- 逐节点写清 LLM 的语义判断、框架的确定性约束及调用方执行/评价责任。明确现有源码链已连接，而本轮真实失败之后的阶段仍未执行。
- 模型能直接阅读并引用反馈的原始文本字段，避免宿主额外嵌套序列化引发机械复制错误；原始反馈与引用校验不能被绕过。
- 参考配置应容纳真实首个摘要的有界纠错请求。单次限制由显式配置控制，不能隐式借用累计预算或自动增加调用次数。
- 保持经验提取、归因、必要性、Skill修改操作、对照准入与发布的语义和权限不变；不针对GDPevo写业务规则。
- 用相同已归档开发经历做一次有界真实回放，报告实际运行阶段、用量与未知项，不在运行中继续调参追求发布。

## Acceptance Criteria

- [x] 责任表和修改清单能逐项对应源码和本次失败证据。
- [x] 原始反馈文本的精确引用可校验并可重读；错误、未读、跨可见性或篡改引用仍拒绝。
- [x] 真实被拒稿派生的修复 fixture 在新参考输入限额内运行两次调用；较低限额仍在第二次调用前拒绝。
- [x] 生成总纲/包与配置一致；受影响的确定性检查、故障注入、独立审查通过。
- [x] 实盘回放保留全部结果，不运行保留集，不把未生成候选或未发布结果改成成功。
