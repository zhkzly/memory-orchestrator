# 当前职责与实际完成边界

基于当前源码及独立只读审查；不以旧 planning 记忆覆盖当前实现状态。

| 节点 | LLM | Framework / 调用方 |
| --- | --- | --- |
| N01 接收原材料 | 无强制模型判断 | 调用方提供经历；Store 保存来源与身份（store.py） |
| N02 选择记忆 | 当前不调用 LLM | context 按任务、关系、依赖和容量选择，保存提供清单 |
| N03 执行任务 | 外部 Agent 决策与工具使用 | sampling 冻结槽位与版本；调用方实现 execute |
| N04 组织轨迹 | 缺标时建议目标关联 | trace/evidence 索引、按角色和调用组裁剪；核查来源，不补造事件 |
| N05 反馈 | 可选代理评审 | 调用方提供 evaluator；feedback 固定准则、聚合并保留缺项与来源 |
| N06 经验 | 局部摘要、提取、请求补读、语义维护 | learning 提供有界原文、核引用、保存草稿/经验与费用 |
| N07 归因与必要性 | 原因假设、是否需要Skill、修改目标和行为差异 | 核查目标/引用/能力比较/材料，无法由字符串校验认证因果 |
| N08 候选 | 生成Skill和资产修改 | candidates 限定操作/路径/版本并建立不可变候选 |
| N09 比较 | 不自行宣布改进成立 | 调用方运行和评分；evaluation 固定对照、计算门槛与排序 |
| N10 发布/回退 | 无绕过准入权限 | release 复核候选/验收/generation并原子提交 |
| N11 报告 | 无需LLM | report/telemetry 汇总原始质量、覆盖、费用和未知项 |

总入口 `engine.evolve()` 调用 learn → compare_candidates → SelectionRecord → publish，无候选则正常返回。该代码链存在，构造检查也覆盖完整周期；真实模型能否产生有用且通过验证的候选，是另外的运行证据。

上次实盘只完成执行、评分、轨迹组织和一份被拒的摘要草稿，未执行提取/归因/提案/对照/发布。不存在必须重建整套框架才能修复的证据。具体分界为：反馈字段的机械表示在框架；摘要内容在LLM；单次及累计容量在显式调用配置，执法和计量在StructuredModel。
