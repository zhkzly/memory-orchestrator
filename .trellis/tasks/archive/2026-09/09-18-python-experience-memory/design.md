# 设计阅读入口（v1.5.0）

产品参考实现已完成。当前完整设计以 docs/blueprint/project-contract.json 为唯一结构化来源，HTML/context 为生成视图。本文件不另定义节点或默认参数；v1.4.1 仅转换工作阶段。

## 两条输入路径

1. 已有经历：EpisodeRecord → N04 索引 / N05 可用反馈 → N06 提取。源版本、context、反馈可以未知。
2. 需要新采样：N01 任务 → N02 固定记忆 → N03 系统计划并调用 execute 函数 → EpisodeRecord / N05 反馈。提供函数负责实际环境，不是核心新建 native 适配器。

两条路径均进入同一经验归集、归因、Skill 生成/修改与候选流程。

## 完整演化责任

N06–N08 负责有界证据、反例、修改对象和一个或多个完整候选；N09 固定 EvaluationPlan 并组织实际比较，记录 EvaluationResult、ValidationRecord 和 SelectionRecord；N10 核对项目/版本/协议/被选身份后发布或回退；N11 汇总全部结果/成本。

execute/evaluate 是当前所需的函数边界，不是未来扩展框架；调用方不需要重新实现这些演化决策。显式触发、任务结束和批次触发可以共用同一核心流程。

## 必须分别理解

- 缺失材料可保存和分析，不等于足以支持归因或发布。
- 回调只是一种调用形式，不决定重复次数、迁移门槛或评分真值。
- 库内发布不等于文件已同步到外部 Agent 项目；具体同步暂缓。
- 关系共现不等于因果；局部修复和迁移收益各按实际评价范围报告。
- 模型输入中的预算/可改范围，与宿主实际检查一致。

当前不规定产品类/文件数量。实现恢复后依据现有消费者落普通函数，不从旧 tests 草稿反推 API。
