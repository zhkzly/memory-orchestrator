# 根因与责任边界

## 有证据支持的诊断

当前 HEAD 6a9a1db 保留 4a71ccf 的产品代码。126 项测试通过，同时本地无模型探针复现 9 个缺口。因此首因不在模型随机性，也不是运行了旧源码；现有测试主要覆盖局部方法，没有闭合实际跨节点的数据/状态契约。

| 已知身份与生命周期的权威关系没有收口 | F02 的另一 run/state 被标 bound；F04 在无回执时写经验；F06/F07 原始材料中的已知事实未被正确消费 | 保存/读取已知源关联的边界、采样记录生成、学习准入；保留未知导入而非强制制造字段 |

## 保留的模型

```text
不可变的任务/运行/事件/反馈事实
       ├── 校验身份与已知组闭合 → 有界结构证据 → 经验与提案尝试
       ├── 计划 × 原始结果/评估 → 报告（允许部分已观察结果）
       └── 唯一候选快照 × 冻结评价协议 → 验证/选择 → 发布
```

报告能看见部分结果，不代表可以据此发布；原文可包含未完成执行的事件，不代表任务成功；来源未知不等于已知矛盾；重复提案不等于多个不同候选。这些区分由现有边界负责，避免每个下游自行解释。

## 具体修正原则

1. 已知本地源关联集中解析/检查，供 Store 的反馈入库和学习入口使用。反馈可能早于 RunBundle 落盘，所以可用已保存的 executions 验证已知 run/artifact；不能把“还没有组回执”误变成不能记录反馈。学习则要另外检查 purpose 与组闭合。外部导入没有本地计划时保留 unknown，不伪造回执。
2. 采样保留提供方实际返回的事件与终态，包括合法 partial events。计划初态和提供方报告的初态若均已知，显式记下是否匹配，不声称宿主实现了环境重置。终态不等于 score，按已冻结的评分政策决定是否请求评价。
3. 结构化证据的来源字段和关联摘要由索引投影，选择、补读、校验都用同一含义。仅披露选中/可读范围所需的结构，预算涵盖正文和元数据；不全量塞入索引。
4. 现有 sampler 产生单一 task_outcome 时，保存明确的评估关联（可使用已有 TaskAssessment），报告据此读原始事实；多标准/加权聚合不在本次默认造出来。旧记录无法唯一绑定时报告未知/歧义，不能选一条恰好通过的反馈。
5. 比较单位为不可变 snapshot；保留 proposal→snapshot 对照与所有提案成本。Validation 是结论，EvaluationResult/Feedback 才是成绩来源；未生成 Validation 的已知结果仍报告，但不会自动 accepted。
6. F01 保持明确政策：独立验收可以评价某些非 completed 执行留下的产物。采样与比较使用相同的终态语义，差异由执行前记录的政策表达，不偷换取消=失败。缺产物、身份错误、必要证据不足依然 unknown。

不增加统一事件总线、通用 lineage 引擎、插件注册器或新的后端层。若需要共享函数，仅限已经有两个以上实际消费者的事实解析、投影或账本读取。

## 验收方式改变

沿数据流验收“已知事实 → 存储 → 模型输入/报告/发布”的交接，而不是只看各模块返回的字段。9 个既有探针是基线，扩展同因的合法边界：无本地源、早到反馈、同文不同结构、非完成但有部分事件、已写结果但未判定、同内容多提案。模型/benchmark 效果继续单独标识，不以本次测试替代。
